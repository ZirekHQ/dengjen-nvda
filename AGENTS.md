# dengjen-nvda Architecture & Guardrails
- **Environment**: NVDA screen-reader add-on in Python 3.13 (Windows-only runtime: gRPC server, vendored native wheels).
- **Core Subsystems & Data Flow**:
  - `addon/synthDrivers/dengjen_neural_voices/`: Synthesizer driver loaded by NVDA, structured as ports-and-adapters (`domain/`, `ports/`, `adapters/`).
    - `adapters/nvda/synth_driver.py`'s `SynthDriver.speak()` transforms speech sequences into `SpeechTask`/`BreakTask`/`IndexReachedTask`/`DoneSpeakingTask` objects; the package `__init__.py` re-exports `SynthDriver` for NVDA's driver discovery.
    - Tasks execute via `process_speech()` on the shared asyncio loop, feeding raw PCM into sample-rate-keyed `WavePlayer` instances.
    - `domain/tts_system.py`'s `DengjenTextToSpeechSystem` manages voice/pitch/rate state and pulls chunks through `ports/tts_backend.py`'s `TTSBackend` protocol.
  - `addon/globalPlugins/dengjen_tts_global_plugin/`: Tray-menu voice manager GUI (imports directly from the synth driver package).
  - `aio.py`: `AsyncEngine` singleton managing dedicated background thread, event loop, and thread pool for async gRPC calls.
  - `adapters/dengjen_grpc/`: the `TTSBackend` adapter; spawns detached `dengjen-tts-grpc.exe` subprocess on an OS-assigned port it reports back through its log, explicitly validates `vcruntime140_1.dll` presence prior to spawn.
  - `_config.py` & `voice_migration.py`: `DengjenConfig` persists per-voice configuration; migration handles legacy Sonata settings on first run.
- **Vendored Dependencies**: Do NOT edit `lib/` directly; refresh native wheels via `update_grpc.py`, `update_miniaudio.py`, `update_cffi.py`, `update_protobuf.py` (stays on 4.25.x). `bin/dengjen-tts-grpc.exe` is not committed: run `python update_dengjen_tts.py fetch` before `scons`/`tests_contract/`; re-pin `dengjen-tts.lock` with `update_dengjen_tts.py bump` (`update-dengjen-tts.yml` opens the bump PR daily, on dispatch, or manually; it skips when a PR for that version exists). gRPC stubs in `adapters/dengjen_grpc/grpc_protos/` are generated by `update_grpc_protos.py` from the release pinned in `dengjen-tts.lock` (needs `grpcio-tools==1.62.3` and Python 3.12 or older: it has no 3.13 wheel); do not hand-edit.
- **Build & Versioning**: SCons-driven (`scons`). Prefer configuring via `buildVars.py` before modifying `sconstruct`. `addon_version` MUST be strict 3-part semver.
- **Release Workflow**: Stable releases go through the `Prepare release` PR (`prepare-release.yml`); merging it tags `vMAJOR.MINOR.PATCH` from `main`. Only `-beta.N` tags are pushed manually: `git tag -a vMAJOR.MINOR.PATCH-beta.N -m "..."`. CI builds on Ubuntu, executes Windows tests, and drafts release artifacts.

# Git & Contribution Conventions
- **Branches**: `fix/<slug>`, `feat/<slug>`, `chore/<slug>`.
- **Commits**: Short imperative subject line, blank line, body explaining *why*, and relevant issue references.
- **PR Titles**: Conventional Commits style (`fix:`, `feat:`, `chore:`, `docs:`).
- **Trailers**: Never include `Co-Authored-By` trailers or AI attribution.
- **Scope**: Keep PRs small, with one purpose each. Before starting a feature over about 500 lines, or one that spans the synth driver, the global plugin and the domain layer, open an issue and wait for a reply. If a change grows past that while you work, stop, split it into separate PRs, and open an issue for the larger plan.
- **Tests**: A new module needs tests under `tests/` (see `.github/CONTRIBUTING.md`, "Adding tests for a new module"). Run `ruff check .`, `ruff format --check .` and `pytest` before pushing.
- **CI**: SonarCloud runs on a fork PR only after a maintainer comments `/sonar`; the gate needs 80% coverage on new code and cognitive complexity of at most 15 per function. CodeRabbit comments are advisory.
- **Process details**: `.github/CONTRIBUTING.md` is the full contributor guide; this file does not repeat it.

# Testing Rules & Mocking Guardrails
- **CRITICAL**: Never stub a base class with `MagicMock()` (subclassing a mock makes class bodies no-ops). Stub NVDA base classes as plain empty classes.
- **Test Matrix**:
  - `pytest` (`tests/`): Unit/stub suite. Runs on Linux and Windows.
  - `pytest tests_contract/`: Real gRPC server integration (Windows only).
  - `pytest tests_gui/`: Real wxPython GUI suite (Windows only).
  - `pytest tests_e2e/`: Full NVDA automation via `nvda-addon-testkit` (Windows CI only).
- **GUI Testing Gotchas (`tests_gui/`)**:
  - Never call `ShowModal()` (causes CI deadlock timeouts); construct -> assert -> `Destroy()`.
  - wx swallows event handler exceptions; assert observable side-effects instead of `pytest.raises`.
  - `gui.messageBox` returns `wx.YES`/`wx.NO`/`wx.OK`/`wx.CANCEL` (not `wx.ID_*`).
  - Key events require explicit `SetId(window.GetId())` or wx drops the event.
  - Walk tab order with `Navigate()`, not `wx.UIActionSimulator`.
